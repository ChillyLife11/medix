# Проверки записи пациента

- `pnpm test` — форма подтверждения, ФИО, отправка визита, ошибки, блокировка повторной отправки и смена аккаунта. API заменены заглушками.
- `pnpm test:browser` — настоящий компонент подтверждения в Chromium/Edge на мобильных размерах и при уменьшенной высоте окна. Запрос создания перехватывается и возвращает тестовую ошибку. Внешние запросы блокируются. Это проверка вёрстки, не замена проверки в MAX на физических Android/iPhone.
- По умолчанию браузер берётся из стандартной установки Microsoft Edge. Для другой установки задайте `EDGE_PATH`.
- `tests/booking-fixture.html` — только локальный стенд. В production-сборку не входит.
- Сборка для компании 3: `VITE_COMPANY_ID=3 pnpm build` (в PowerShell задайте переменную через `$env:VITE_COMPANY_ID='3'`).

Проверены существующие серверные тесты `tests/regression/appointment_client_profile_api.php` в отдельном репозитории medix.local: сохранение ФИО, пустое отчество, откат транзакции и запрет изменения чужого профиля проходят, NETWORK_CALLS=0. Сценарий «legacy API сохраняет имя и фамилию» ожидает объект ProfileApiAppointment, тогда как актуальный actionCreate возвращает массив результата writeResponse. Полный серверный набор не является зелёным; серверный код и фикстуры этой задачей не изменяются.
